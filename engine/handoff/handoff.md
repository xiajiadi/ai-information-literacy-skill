## 0. 这份文件是什么 / 不是什么

**是**：一份**经验传递**。记录上一轮架构里哪些判断被实战证明是对的、哪些坑真实存在、
以及在新的淘汰赛情境下这些经验应当怎样被**改造**而不是**照搬**。

**不是**：一份可以直接运行的架构说明书，也不是配置清单。**不要按这份文件的形态重建系统。**
上一轮的配置（`config/*.yaml`、`scripts/*.py`）可以读、可以抄片段，但**整体形态是为校赛设计的，
淘汰赛的题目分布、时间压力、平台集合都可能不同 —— 直接复用会把你锁死在旧假设里。**

📎 配套资产见 `handoff/question_bank.md`（291 道题的三段式整理 + 407 个网址的分类列表）。

## 1. 情境变化：为什么必须大改

| 维度 | 校赛初赛（上一轮） | 省赛淘汰赛（本轮） | 影响 |
|---|---|---|---|
| **题目来源** | 公开样题 + 三套模拟题大量重合 | 必然出新题，原题命中率会**断崖下降** | 「题库命中」从主路径降为**兜底路径** |
| **题目形态** | 50 题客观题（20单选+20多选+10判断），每 2/2.5/1 分 | 淘汰赛，未知；可能更重实操、综合性更强 | 模板化答题可能不够用 |
| **时间压力** | 单题相对宽裕 | 淘汰赛通常**更快淘汰**，容错更低 | 时间预算必须重设 |
| **环境条件** | 本机可联网、可用浏览器 | 未知（是否允许联网/是否限时/是否监考） | **必须把"无外部依赖"当作一种可能** |
| **竞争性质** | 达标 | 淘汰 | 「求稳」的权重高于「求全」 |

**一句话**：上一轮的核心资产是**一张覆盖了原题的网**；本轮你要造的是**一台能处理没见过的题的机器**。
网要留着当兜底，但不能当主力。

## 2. 已被实战验证的设计（值得借鉴，形态必须变）

下面每一条都经过 2026-09-19 校赛真实检验。**保留其"意图"，重设计其"形态"。**

### 2.1 三段式降级匹配

**做法**：`Exact Match → Variant Match → Platform Recipe → Manual Handoff`，
每一段失败了才降级到下一段，绝不跳级。

**为什么有效**：150 道模拟题原题命中 **150/150**，选项重排后仍 **150/150**（毫秒级）；
同型题识别在 4 个随机种子下 **40/40**。降级路径让"快"和"准"不互相干扰。

**淘汰赛要怎么改**：第一段（原题命中）的命中率会暴跌，**不要因为它失效就拆掉它** ——
它是兜底。真正要加厚的是第二段与第三段：把「同型题匹配」升级为
**「任务类型识别」**（见 4.2）。

### 2.2 同型题复用「配方」，绝不复用「答案」

**做法**：正式题换参数时（课程A→课程B、年份2014→2017），
系统进入 `OFFICIAL_MOCK_VARIANT` 状态，**复用旧题的操作路径，但答案字段强制为空**。

**为什么有效**：这是整个架构里**最重要的一条纪律**。有一次我几乎把"参照题答案"当成
"变体题答案"，代码层面直接堵死了这条路（`tests/test_variant_match.py` 里有契约测试）。

**淘汰赛要怎么改**：这条**必须原样继承**，没有商量余地。参数变了答案必然不适用，
任何"看起来很像所以直接用"的捷径都会在淘汰赛上翻车。

### 2.3 平台 Recipe 优先于从零检索

**做法**：把「平台 → 入口 → 检索项 → 匹配方式 → 筛选位置」固化成配方；
遇到该平台的题，**先查配方，不要先想"怎么搜"**。

**为什么有效**：7 个平台的实测配方一次做好，之后每题省下 30-60 秒。
实测最有价值的三条：
- CNKI 走 `kns.cnki.net/starter/advanced`（**直连 `kns8s/AdvSearch` 会撞验证码**）
- ScienceDirect 走 `/search`（**首页被 Cloudflare 拦**）
- 维普走 `/advancesearch`（**旧入口 `qikan.cqvip.com` 返回 412**）

**淘汰赛要怎么改**：配方本身要重做（平台集合会变），但"**先固化入口再答题**"这个动作要保留。
省赛前应当把**点名平台的首页/检索页/高级检索页逐个实测一遍**，
记录"哪个入口能用、哪个是陷阱"。

### 2.4 深链接优先，首页往往是错的入口

**做法**：题目写了平台名，就直接跳该平台的**功能页**，不要从首页层层点击。

**为什么有效**：实测中约 **1/3 的平台，其首页并不是正确入口**：
- IEEE Xplore → `ieeexplore.ieee.org/search/advanced`（不是 ieee.org）
- 国家自然科学基金结题项目 → `kd.nsfc.cn/finalProjectInit`（不是首页找"信息检索"）
- CNIPA 专利 → `pss-system.cponline.cnipa.gov.cn/conventionalSearch`
- 百度指数行业排行 → 必须**手动指定历史日期**，默认日期显示「暂无数据」

**淘汰赛要怎么改**：把"深链接表"从**题目驱动**改为**平台驱动** ——
按平台而不是按题号组织，这样新题来时不用查题号。

### 2.5 人工交接必须格式固定

**做法**：转人工时**必须**给全四样，缺一不可：

    🔴 需要你操作
    官网：<URL>
    1. <入口路径>
    2. <可复制检索式或筛选条件>
    3. <看哪个字段>
    复制：<可直接粘贴的表达式>
    看：<需要回传的结果>

**为什么有效**：这条让"我卡住了"变成"你 30 秒能搞定"。
实战中约 6 道题走了这条路，人机配合没有一次因为"交接不清楚"而浪费。

**淘汰赛要怎么改**：保留格式。但**把触发时机大幅前移** ——
上一轮是"卡住才交接"，淘汰赛应当**"预计会卡就交接"**（见 4.5）。

### 2.6 证据分级，绝不把旁证当官方

**做法**：`🟢 官方源实测` / `🟠 旁证（第三方/聚合）` / `🔴 需人工`。
第三方来源永远标注为辅助证据。

**为什么有效**：有 4 道题我是靠第三方数据答的（律师协会、同花顺、
Crossref、万方著录记录），**都明确标了 🟠**，你才能判断要不要复核。
如果我把它们伪装成 🟢，你可能就少复核一道错题。

**淘汰赛要怎么改**：**原样继承**。淘汰赛容错更低，证据分级只会更重要。

### 2.7 时间预算硬约束 + 风控纪律

**做法**：单题 NORMAL 180s / FAST 120s 硬超时，到点强制转人工；
同一路线自动化失败 2 次即停。

**为什么有效**：防止在一道题上烧掉全局时间。
**更重要的教训**：**CNKI / 万方 / 维普 会因连续检索触发风控**。
我在一次会话里对 CNKI 连发七八次检索，直接触发 blockPuzzle，**之后整个会话都用不了**。

**淘汰赛要怎么改**：把"风控预算"提升为一等公民 ——
**每个平台限定检索次数，超了就转人工，而不是重试**。

## 3. 十条真实教训（都是当场踩到的）

| # | 教训 | 具体案例 |
|---|---|---|
| 1 | **运算符语义因平台而异，且会反转结论** | CNKI 单框内 `*`=与、`+`=或。用 `+` 得 1,800,162 条、榜首方鹏骞(400)；用 `*` 得 15,802 条、榜首**王浩(36)**。**同一道判断题，用错符号答案相反** |
| 2 | **选项字母 ≠ 选项内容** | GB/T 7714 文献类型标识题，选项是 A.J / B.C / C.D / D.M —— **字母和内容都是字母**。我选了 C（内容 D），正确答案是 D（内容 M） |
| 3 | **筛选要"先设条件再检索"** | 维普「标准状态=作废」若在检索**之后**才勾选，不生效。自证方法：分面数字之和 7933+2690+35=10658=结果总数 → 说明筛选没生效 |
| 4 | **平台默认值会误导** | 万方高级检索**默认「模糊」不是「精确」**；百度指数行业排行**默认日期下无数据**（必须手动选历史日期） |
| 5 | **页面字段名 ≠ 题目问的字段** | CNKI 结果页左侧的「学科」是**专辑分类**，不是学位论文的「学科专业」——必须进详情页 |
| 6 | **题目要的字段可能不存在于界面** | 维普高级检索**没有「导师」字段**（只在专业检索里）；此时不要硬试，直接换路径 |
| 7 | **扫描件 PDF 没有文字层** | 川大规范 PDF 是 18 页纯图片，pypdf 抽取全为 0 字符 → 必须**浏览器渲染后目视读取** |
| 8 | **自动化点击常常无效，要改用页面自身 API** | 万方智研、国家社科基金、国图资源服务、NSTL 词表的筛选控件都不响应合成点击；改用其 XHR 接口或直接调用页面函数才成功 |
| 9 | **登录墙/WAF 是常态，不是异常** | zxgk.court.gov.cn 返回 **412**；Wiley 是 Cloudflare；CNKI 是 blockPuzzle；万方是滑块；AI知数/LeapSpace/DOUBAO 要登录 |
| 10 | **第三方能救命，但不能冒充官方** | 律师执业证号、专利申请、Crossref 作者名单都靠旁证拿到 —— 全部标 🟠，由人复核 |

## 4. 新架构建议（淘汰赛版）

以下是我认为**必须做出的大改**。请批判地看，不要照单全收。

### 4.1 从「题库中心」转向「平台能力中心」

上一轮的数据结构是 `题目 → 答案`。淘汰赛应当改为：

    平台 → 能力（能按什么字段检索 / 有什么筛选 / 结果怎么读）→ 可回答的问题类型

理由：新题的"内容"会变，但**平台的检索能力是稳定的**。
把能力固化下来，新题只是"用已有能力回答新参数"。

### 4.2 把「同型题匹配」升级为「任务类型识别」

上一轮匹配的是"这道题像哪道旧题"。淘汰赛应当识别：

    这道题要做的**动作**是什么？
    ├ 取一个数（结果数量 / 年份 / 排名第N）
    ├ 取一份名单（作者 / 机构 / 岗位 / 关键词）
    ├ 核对一个字段（学科专业 / 文献类型 / 状态 / 立案时间）
    ├ 判断一个存在性（有没有某功能 / 某栏目 / 某条目）
    └ 比较两个值（哪个更大 / 哪个更多）

**动作类型只有五六种，且不会变**。识别出动作，就能直接选方法，不必依赖旧题。

### 4.3 把「检索式生成」提升为一等公民

上一轮我把检索式藏在各平台配方里。淘汰赛应当独立出来：
**给定「平台 + 字段 + 词 + 逻辑 + 时间」，直接吐出可复制的检索式**。
配套已有的 `config/query_templates.json`（10 个模板）作为起点。

**铁律**：不同库的语法不可混用（CNKI 的 `*` 不能套到万方，PubMed 的 `[Title]` 不能套到 IEEE）。

### 4.4 建立「入口可信度表」

把每个平台的入口分成三档：

| 档 | 含义 | 例 |
|---|---|---|
| ✅ 直连可用 | 实测能打开 | CNKI `starter/advanced`；维普 `advancesearch` |
| ⚠️ 会跳验证 | 需人工或换路 | CNKI `kns8s/AdvSearch` → blockPuzzle |
| ⛔ 不可用 | 直接放弃 | 维普 `qikan.cqvip.com` → 412 |

**赛前把点名平台逐个实测填表**，考场上不再临场试错。

### 4.5 人工交接前移

上一轮是"卡住 90 秒 → 交接"。淘汰赛应当：
**识别到"这一步必然需要登录/验证码"时，第一秒就交接**，不要先试两次再说。
把省下的时间留给能自动化的题。

### 4.6 无外部依赖降级方案

**如果淘汰赛环境不允许联网或限制工具**，上一轮的架构会整体失效。
应准备一套**纯知识兜底**：常见平台的默认值、检索语法、字段名、标准编号含义
（如 GB/T 7714 的 `M/C/J/D/N/S/P`）—— 这些不查也能答。

## 6. 未解决的问题（交给下一轮）

1. **Mendeley 类题无法自动化** —— 必须装桌面客户端，本机没装，我当时只能靠推断。
   淘汰赛若再考桌面软件题（Zotero/CiteSpace/VOSviewer），**要提前装好**。

3. **维普「导师」字段只在专业检索** —— 专业检索入口当时点不动，没跑通。
4. **多选题"全选 4 个"是否合法** —— 规则写"2—4 个正确答案"，但实战中 WILEY 那题
   四个选项全是作者，我判了全选，**无法确认对错**。这题至今存疑。
5. **淘汰赛的具体形态完全未知** —— 题型、时间、是否允许联网、平台集合，
   这份文件里的所有建议都建立在校赛的观察上，**请以实际规则为准**。

## 7. 最后一句

上一轮最大的价值不是那 291 道题，而是**「不猜」这条纪律**：
知道自己没验证时，明确说"未验证"；知道是旁证时，标 🟠 而不是 🟢。

淘汰赛压力更大，**这条纪律只会更重要**。宁可交一道标着"需要你确认"的题，
也不要交一道看起来很确定的错题。
