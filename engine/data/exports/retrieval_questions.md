## 三、判定口径与已知字段陷阱

**使用的可靠信号**（按可靠性）：
1. `module_id` ∈ 检索模块集 → 最可靠
2. `question_routes.platform_key` + `config/official_urls.json` 的 `route_type` ∈ {QUERY_RECIPE, ADVANCED_SEARCH, DATABASE_ENTRY, LOGIN_DASHBOARD} → 命中 31 题
3. `variant_match.detect_template()` 返回 B/C/D/E/J/L/M 且题干含检索关键词
4. 题干含「多少/几篇/最接近/发文量/被引/作者是」→ 强制判为实操

**不可用的字段（实测确认）**：

| 字段 | 问题 |
|---|---|
| `module_name` | **被污染**：`module_id=知识模块21` 却写着「信息检索理论与技术-中国图书馆分类法」；90+ 个 distinct 值。**只能用 module_id** |
| `official_platform` | **248/248 行全为空字符串** |
| `retrieval_path` | 实为「答案来源/解题说明」，不是检索路径（93 行是「公开样题原始答案/解析」） |
| `retrieval_query` | 244/248 行 == `question_text` 原文，无区分度 |
| `retrieval_fields` / `retrieval_filters` / `current_observed_value` | 分别只有 4 / 1 / 0 行非空 |
